# Demo readiness

Do not add feature scope. Inspect what actually runs and focus on a repeatable judge demonstration.

1. Verify one-command local startup and camera permission instructions. Run any available automated smoke tests and report failures verbatim.
2. Give a stepwise live demo: two people appear; person A deliberately covers both eyes; A becomes blurred live; A lowers hands; A stays blurred; B stays visible; A leaves and returns; attempted protection restoration is displayed honestly; voice route shown only if real Muse access works.
3. Validate recording: original and protected written at capture time with aligned duration/timestamps; both playable after Stop closes encoders; original never fed to public preview. If checks cannot run here, supply exact manual commands/checklist.
4. Propose a 5-minute continuous runtime observation: actual frame rate, gesture activation time, false triggers, identity switches, stale shields, overheating on MacBook Air M3/M4. Never fabricate measurements.
5. Prepare two scripts: a concise ~60-second talk track and a 2-3-minute live demo flow. Differentiate proven prototype behavior from future Meta platform integration.
6. Identify the single biggest likely demo failure and one practical fallback (an explicitly labeled pre-recorded demo video). Do not fabricate SDK integrations, model evaluations, or unbypassable glasses-level protections.

Output `Ready`, `At risk`, and `Blocked` with evidence and exact next action.
